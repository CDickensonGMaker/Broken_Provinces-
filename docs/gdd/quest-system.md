# Quest System GDD

**Version:** 1.0
**Last Updated:** 2026-05-25
**Status:** Implemented

---

## 1. Overview

The quest system manages all player objectives from main story progression to procedural bounties. It supports linear quests, quest chains, timed objectives, multiple completion methods, and branching consequences.

**Core File:** `scripts/systems/quests/quest_manager.gd`

---

## 2. Player Fantasy

Players experience a living world where their actions have consequences. Quests aren't just checklists—they're opportunities to make meaningful choices that affect faction relationships, unlock companions, and shape the world.

---

## 3. Quest Structure

### 3.1 Quest Class

```
Quest
├── id: String (unique identifier)
├── title: String
├── description: String
├── state: QuestState (UNAVAILABLE, AVAILABLE, ACTIVE, COMPLETED, FAILED)
├── completion_state: QuestCompletionState (NONE, COMPLETED, FAILED, BETRAYED)
├── is_main_quest: bool (gold markers vs teal)
├── objectives: Array[Objective]
├── rewards: Dictionary
├── prerequisites: Array[String] (quest IDs)
├── flag_prerequisites: Array[String]
├── forbidden_flags: Array[String]
├── quest_source: QuestSource
├── giver_npc_id: String
├── turn_in_type: TurnInType
├── turn_in_target: String
├── next_quest: String (auto-start on completion)
├── trigger_item: String (start quest when item picked up)
├── starter_items: Array[Dictionary]
├── spawn_on_accept: Array[Dictionary]
├── quest_items: Array[String] (temptation tracking)
├── faction: String
├── cooldown_days: int (bounty cooldown)
├── possible_zones: Array[String] (random zone selection)
├── dungeon_type: String (procedural dungeon generation)
└── choice_consequences: Dictionary
```

### 3.2 Objective Class

```
Objective
├── id: String
├── description: String
├── type: String
├── target: String
├── target_zone: String
├── required_count: int
├── current_count: int
├── is_completed: bool
├── is_optional: bool
├── completion_method: String (tracks HOW completed)
├── time_limit: int (seconds, 0 = no limit)
├── fail_quest_on_timeout: bool
└── dungeon_spawn: Dictionary
```

## 4. Objective Types

| Type | Target | Description | Example |
|------|--------|-------------|---------|
| `kill` | enemy_id | Kill enemies of type | "goblin", "goblin_soldier", "enemies" |
| `collect` | item_id | Collect items | "wolf_pelt", "ancient_coin" |
| `talk` | npc_id | Talk to NPC | "elder_marcus", "guard_captain" |
| `reach` | location_id | Reach location | "dalhurst", "bandit_hideout" |
| `interact` | object_id | Interact with object | "bounty_board", "altar_of_time" |
| `deliver_soulstone` | soulstone_id | Turn in soulstone to NPC | "greater_soulstone" |
| `solve_puzzle` | puzzle_flag | Complete puzzle | "crystal_hearts_solved" |
| `recruit_follower` | follower_id | Recruit companion | "martha_barmaid" |
| `wave_defense` | spawner_id | Survive waves | "arena_wave_spawner" |
| `escort` | escort_id | Escort NPC to destination | "merchant_convoy" |

### Kill Objective Matching

Kill objectives support hierarchical matching:
1. **Exact match**: "goblin_soldier" matches only "goblin_soldier"
2. **Category match**: "goblin" matches "goblin_soldier", "goblin_archer", etc.
3. **Generic match**: "enemies" matches any enemy

| State | Description | Reputation |

| `COMPLETED` | Normal completion | Full reward |
| `FAILED` | Failed objectives | Negative rep |
| `BETRAYED` | Kept quest items or selfish choice | Severe negative rep |

## 8. Timed Objectives

Objectives can have time limits that create urgency:

```json
{
  "id": "rescue_hostage",
  "description": "Rescue the hostage before time runs out",
  "type": "interact",
  "target": "hostage_cage",
  "time_limit": 300,
  "fail_quest_on_timeout": true
}
```

### Timer API

| Function | Description |
|----------|-------------|
| `start_objective_timer(quest_id, obj_id, seconds)` | Start timer |
| `stop_objective_timer(quest_id, obj_id)` | Cancel timer |
| `pause_objective_timer(quest_id, obj_id)` | Pause for cutscenes |
| `resume_objective_timer(quest_id, obj_id)` | Resume timer |
| `get_objective_time_remaining(quest_id, obj_id)` | Get remaining time |
| `extend_objective_timer(quest_id, obj_id, extra)` | Add extra time |

### Timer Behavior

- Timers pause when game is paused
- Completing objective stops its timer
- Timer starts for next timed objective automatically
- `fail_quest_on_timeout: false` allows optional timed objectives

## 10. Quest Prerequisites

### Quest Prerequisites

```json
{
  "prerequisites": ["main_quest_01", "side_quest_rescue"]
}
```

All listed quests must be COMPLETED before this quest is available.

### Flag Prerequisites

```json
{
  "flag_prerequisites": ["chronos_devotee", "adventurers_guild_rank_veteran"]
}
```

All flags must be SET via FlagManager.

### Forbidden Flags

```json
{
  "forbidden_flags": ["gaela_devotee", "morthane_devotee"]
}
```

Quest unavailable if ANY of these flags are set.

## 11. Choice Consequences

Quests can define consequences for dialogue choices:

```json
{
  "choice_consequences": {
    "spare_bandit_leader": {
      "flags_to_set": ["spared_grimshaw"],
      "reputation_changes": {"bandits": 20, "guards": -10},
      "unlock_follower": "grimshaw"
    },
    "execute_bandit_leader": {
      "flags_to_set": ["executed_grimshaw"],
      "reputation_changes": {"guards": 20, "bandits": -30},
      "spawn_enemy": "bandit_avenger@crossroads"
    }
  }
}
```

Applied via `QuestManager.apply_choice_consequence(quest_id, choice_id)`.

---

## 12. Temptation System

Quest items can be marked for temptation tracking:

```json
{
  "quest_items": ["nobles_signet_ring", "ancient_artifact"]
}
```

If player SELLS or EQUIPS a quest item:
- Quest state → FAILED
- Completion state → BETRAYED
- Negative faction reputation applied

## 13. Spawn On Accept

Spawn objects when quest is accepted:

```json
{
  "spawn_on_accept": [
    {
      "type": "chest",
      "location": "bandit_hideout",
      "coords": [50, 0, 30],
      "contains": ["quest_letter"],
      "loot_tier": "common"
    },
    {
      "type": "hostage",
      "location": "bandit_hideout",
      "hostage_id": "kidnapped_merchant",
      "name": "Gerald the Merchant",
      "objective_id": "rescue_hostage"
    }
  ]
}
```

Spawned objects are cleaned up if quest fails.

## 14. Bounty Cooldown System

Bounties have cooldowns to prevent spam:

```json
{
  "cooldown_days": 5,
  "possible_zones": ["elder_moor", "thornfield", "dalhurst"]
}
```

| Function | Description |
|----------|-------------|
| `is_bounty_on_cooldown(quest_id)` | Check if bounty available |
| `get_bounty_cooldown_remaining(quest_id)` | Days until available |
| `clear_bounty_cooldown(quest_id)` | Remove cooldown |

## 15. Quest Chains

Quests can auto-start follow-up quests:

```json
{
  "id": "main_quest_01",
  "next_quest": "main_quest_02"
}
```

When `main_quest_01` completes, `main_quest_02` starts automatically.

## 17. Procedural Dungeon Quests

Quests can generate dungeons:

```json
{
  "dungeon_type": "crypt",
  "dungeon_seed": 0,
  "dungeon_room_set": "crypt_rooms",
  "dungeon_size": "MEDIUM"
}
```

Seed 0 = hash of quest_id for reproducibility.

## 18. Navigation Integration

### Objective Location Caching

When quest starts, objective locations are cached for compass navigation:
- Kill objectives: Found dynamically in scene
- Talk objectives: NPC location or target_zone
- Reach objectives: WorldGrid location
- Turn-in: Cached as `_turnin` special key

### Navigation API

| Function | Returns |
|----------|---------|
| `get_objective_hex(quest_id, obj_id)` | Vector2i grid coords |
| `get_objective_zone(quest_id, obj_id)` | Zone ID string |
| `get_objective_world_pos(quest_id, obj_id)` | Vector3 world position |
| `get_turnin_hex(quest_id)` | Turn-in grid coords |
| `get_turnin_zone(quest_id)` | Turn-in zone ID |

## 23. Edge Cases

### Empty Objectives
- Quest with no objectives auto-completes on start if AUTO_COMPLETE

### Mid-Quest Save
- All objective progress is saved
- Timed objectives resume with saved remaining time

### NPC Death Mid-Quest
- If giver/turn-in NPC dies, quest may become uncompletable
- Consider using NPC_TYPE_IN_REGION for resilience

### Duplicate Progress
- `update_progress()` is idempotent per objective
- Completed objectives ignore further progress

### Pre-Collection
- When quest starts, existing inventory is checked for collect objectives
- Items already owned count toward progress
